# sibur.ru-ART — страница проекта «АртНаЗавод»

Интерактивная страница проекта «АртНаЗавод» (муралы на предприятиях СИБУРа)
для встраивания в действующий sibur.ru как раздел с long scroll — не
отдельный сайт.

Собран на дизайн-системе SIBUR (`@sibur/design-system-react`), работает на
реальном контенте заказчика: 35 арт-объектов, 11 городов, 2022 — декабрь 2025.

## Стек и требования

- Node.js 24 (собиралось на 24.18), npm 11
- React 19 + TypeScript + Vite 8, SCSS
- `@sibur/design-system-react` 3.8.x, `@sibur/design-tokens` 3.1.x
- Leaflet + markercluster (карта объектов, спутниковые тайлы Esri)

Пакеты `@sibur/*` живут во внутреннем Artifactory, а не в публичном npm —
реестр прописан в `prototype/.npmrc`. Чтение открыто без токена, нужен только
доступ в DEV-контур и доверие к корневому сертификату `DevRootCA`:

```bash
export NODE_EXTRA_CA_CERTS=/путь/к/devrootca.crt
```

Сертификат лежит в платформенной документации DEV-контура; без него npm
упрётся в самоподписанный TLS на `repo.dev002.local`.

## Быстрый старт

Репозиторий использует **Git LFS** для видео (19 файлов, ~440 МБ):

```bash
git lfs install
git clone https://gitlab.dev002.local/tribes/itcm-tribe/sibur-web-portal-team/sibur-web-portal-system/sibur.ru-art.git
cd sibur.ru-art/prototype
npm ci
npm run dev      # локальная разработка
npm run build    # прод-сборка в prototype/dist/
```

Если репозиторий клонирован без LFS, видео подтягиваются потом:
`git lfs pull`.

## Развёртывание

Сборка — обычная статика (`prototype/dist/`), отдаётся любым веб-сервером.
Отработанная схема: nginx, `root` на каталог сборки, `try_files ... /index.html`
для клиентского роутинга.

**Критично при встраивании в sibur.ru.** Раздел живёт не в корне домена, а в
поддиректории за прокси, поэтому в сборке нет ни одной ссылки от корня:
`vite.config.ts` задаёт `base: './'`, рантайм-пути к фото, видео и логотипам
тоже относительные. Из этого следует требование к прокси: **URL раздела должен
отдаваться с завершающим слэшем** (`/art-na-zavod/`, не `/art-na-zavod`) —
иначе браузер разрешит относительные пути на уровень выше и ассеты не
загрузятся. Обычный `location` с редиректом на слэш это обеспечивает.

Проверено на прод-сборке: страница поднята из вложенного каталога, все ассеты,
фото и видео отдаются 200, абсолютных путей от корня в разметке нет.

## Что в репозитории

| Путь | Что это |
| --- | --- |
| `prototype/` | само приложение (исходники, ассеты, скрипты сборки контента) |
| `prototype/public/photos`, `media`, `hero` | фото и видео объектов, видео — через LFS |
| `extraction/` | разбор презентации заказчика: `registry.json` + `REGISTRY.md` (реестр 35 объектов и явный список пробелов в исходных данных) |
| `measure/` | замер визуального языка действующего sibur.ru (типографика, палитра, радиусы) и отчёт сравнения с дизайн-системой |
| `HANDOFF-agency.md` | описание прототипа для внешнего подрядчика |
| `CLAUDE.md` | подробный рабочий журнал: какое решение принято, почему и что проверено |

Намеренно **не** в репозитории: исходные `.pptx`/`.docx` заказчика, мастера
видео (`content/`, ~914 МБ) и сырые превью из презентации — это рабочее сырьё,
для сборки не нужное.

## Открытые вопросы к заказчику

Прототип показывает пробелы исходных данных плейсхолдерами, а не выдумками:

- точные координаты объектов (карта расставляет метки по городам);
- художник не указан у 31 объекта из 35, год — у 5, описание — у 3;
- конфликт года у объекта «Батискаф» (АГХК): 2025 против 2024 в разных слайдах;
- права на публикацию фотографий вне фотобанка photo.sibur.ru.

Полный список с обоснованием — в шапке `extraction/REGISTRY.md`.
