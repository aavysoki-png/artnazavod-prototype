# «АртНаЗавод» — пакет передачи агентству

> Прототип страницы проекта «АртНаЗавод» для sibur.ru. **Это не продакшн**:
> не Битрикс, не CMS, не интеграция в контур sibur.ru, не проходил ИБ.
> Задача прототипа — заменить отсутствующие макеты и зафиксировать поведение
> и структуру, которые словами передать сложнее, чем показать работающими.
> Перенос в Битрикс — задача агентства; этот документ и есть точка входа.

## Как посмотреть

```bash
cd prototype
npm install
npm run dev
```

Откроется на `http://localhost:5173` (или следующем свободном порту).
Прототип — обычное SPA на React + Vite, без сервера и без бэкенда: все
данные (реестр объектов) зашиты в сборку.

## Структура страницы (сверху вниз)

1. **Первый экран** — полноэкранное фото (сейчас плейсхолдер — фирменный
   градиент, ждём права на публикацию, см. «Открытые вопросы» ниже), логотип
   СИБУРа, название, слоган, три ключевых показателя.
2. **О проекте** — короткое описание концепции.
3. **Ключевые показатели** — расширенная версия цифр первого экрана + разбивка
   по городам.
4. **История проекта** — горизонтальная лента по годам реализации.
5. **Карта** — плейсхолдер географии (см. «Открытые вопросы»: координат нет).
6. **Плитка объектов** — без отдельного заголовка секции, это осознанное
   решение по ТЗ, не пропуск.
7. **Процесс создания** — как рождается сюжет мурала, на реальном
   задокументированном примере (не выдуманный обобщённый процесс).

## Две механики, которые нельзя понять из статичного макета

### Inline Expansion (плитка объектов)

Клик по карточке разворачивает её **в потоке страницы**: разворачивается
на всю ширину плитки, соседние карточки автоматически перетекают ниже.
Повторный клик — сворачивает обратно. Это не popup, не drawer, не переход на
отдельную страницу — ТЗ заказчика прямо запрещает эти три паттерна.

Технически: одна и та же карточка в двух состояниях (`ObjectCard.tsx`), в
раскрытом состоянии получает CSS `grid-column: 1 / -1` внутри CSS Grid —
браузер сам пересчитывает поток, без JS-позиционирования. При переносе в
Битрикс это можно воспроизвести на любом стеке, который умеет: (а) CSS Grid,
(б) переключение класса по клику. Ничего специфичного для React в этой
механике нет.

### Deep Link (ссылка на конкретный объект)

У каждого объекта — ЧПУ-слаг (например `#kos-stihi-tukaya`). Переход по
прямой ссылке на объект: скроллит к нему и сразу раскрывает его карточку —
без перезагрузки страницы, без сервера. Реализовано на `location.hash` +
`history.replaceState` (`useDeepLink.ts`) — переносится на любой стек,
специальной серверной логики не требует, только клиентский JS.

## Реестр объектов — источник контента

`extraction/registry.json` (полные структурированные данные) и
`extraction/REGISTRY.md` (то же самое человекочитаемо, с явным разделом
«Список дыр» наверху) — это единственный источник фактов, из которого
собран прототип. Копия данных в прототипе — `prototype/src/data/objects.ts`
(тот же реестр, вручную перенесён с добавлением `slug` для Deep Link).

**35 объектов, 11 городов, 2022–2026.** Правило, которое соблюдалось
при сборке и должно соблюдаться при переносе: опечатки и незавершённые
названия из презентации заказчика (например «Синтез полиефинов»,
«Воронежы», плейсхолдеры «??») не исправлялись молча — в прототипе показана
исправленная форма, а расхождение с оригиналом зафиксировано в реестре как
пояснение. Не подставляйте правдоподобные данные там, где реестр честно
говорит «не указано» (год, описание, художник) — это касается некоторых
объектов, полный список — в разделе «Список дыр» `REGISTRY.md`.

`extraction/previews/` — рабочие превью изображений из презентации.
**Не использовать на сайте** — это сжатые иллюстрации для слайдов, не
исходники для публикации. Настоящие фото — из фотобанка `photo.sibur.ru`,
права на них — открытый вопрос заказчику (см. ниже).

## Что ТЗ прямо исключает (не реализовывать)

Поиск, фильтрацию, отдельные страницы объектов, popup/drawer, сложные
анимации и переходы. В прототипе этого нет намеренно — не пропуск.

## Открытые вопросы к заказчику (ещё не решены)

Прототип собран честно на том, что уже подтверждено, но следующее пока не
получено или не полностью закрыто:

- **Фото объектов** — в прототип подставлены реальные фото из публичного
  фотобанка `photo.sibur.ru` (поиск по тегу «Промышленное искусство», id
  8203), скачаны напрямую через штатную кнопку «Скачать» фотобанка.
  Сопоставление — на уровне ПЛОЩАДКИ, не конкретного мурала: фотобанк
  группирует снимки по предприятию, а не по названию объекта, поэтому нет
  надёжного способа автоматически определить, какое фото — какой именно
  мурал среди нескольких на одной площадке (см. `prototype/src/data/photos.ts`
  — там же пояснение принципа). Право использования конкретных кадров ЗА
  ПРЕДЕЛАМИ самого фотобанка (то есть публикация на sibur.ru) отдельно не
  подтверждено — это остаётся открытым вопросом для продакшна, доступность
  фото для скачивания из корпоративного фотобанка не равна разрешению на
  внешнюю публикацию.
- **Координаты объектов для карты** — в исходных материалах координат нет ни
  у одного объекта. Карта — тонированная заглушка с списком городов текстом,
  без произвольно расставленных пинов.
- **5 объектов без года, 3 без описания, 1 конфликт года** («Батискаф»,
  АГХК — два разных года на соседних слайдах презентации) — полный список с
  формулировками see `extraction/REGISTRY.md`.
- **Художник/автор** не указан почти нигде (31 из 35) — системный пробел
  исходника, не наш недосмотр.

Прототип прошёл автоматический гейт композиции (вёрстка/адаптивность/
доступность — наложения элементов, горизонтальный скролл, нерезолвящиеся
CSS-переменные, консольные ошибки) на десктопе (1440px) и мобильном (390px)
— оба зелёные. Отчёт: `prototype/evidence/visual-check/report.md`,
скриншоты каждой секции — там же.
