# Обновление фото в галерее «АртНаЗавод»

Инструкция для агента (Claude Code), которому поручили заменить или
дополнить фотографии объекта на странице
[sibur.ru/ru/artnazavod](https://www.sibur.ru/ru/artnazavod/). Всё нужное —
в этом репозитории и на публичной ссылке Я.Диска, доступа к другим машинам
не требуется.

**Твой результат — pull request с готовыми фото, прошедший проверку, и
ссылка на превью.** Сайт ты не собираешь и не выкладываешь: пакеты
дизайн-системы лежат во внутренней сети СИБУРа, а видео в этом репозитории
нет. На каждый PR GitHub Actions сам проверяет фото и выкладывает превью
страницы; после мержа владельцем фото уходят на сайт автоматически.

Остальной `CLAUDE.md` — рабочий журнал проекта. Для этой задачи он не
нужен, читать его целиком не надо.

## Что должен дать человек

1. **Какой объект** — название мурала или предприятия, как на сайте
   («Гармония», «Полимерная шишка»).
2. **Ссылку на Я.Диск** — либо на папку альбома, либо на всю поставку
   `https://disk.yandex.ru/d/12tsuaJPbYuOeQ` (альбом тогда найдётся по
   имени папки).
3. По желанию — **какое фото сделать обложкой** (имя файла на Я.Диске).
   Обложка показывается в свёрнутой карточке и первой в карусели.

Если чего-то не хватает — спроси, не угадывай. Особенно объект: у
нескольких муралов похожие названия.

## Как устроено

- Список объектов и их тексты — `prototype/scripts/final-content-manifest.json`.
  У каждого объекта есть `slug` (имя папки с фото на сайте) и
  `sourceFolders` (имя папки альбома на Я.Диске, например
  `НКНХ_Гармония`).
- Сырые фото альбома скачиваются в
  `Финальная фактура 2026-09-10/<имя папки альбома>/` в корне репозитория.
  Эта папка в `.gitignore` — **исходники в git не попадают никогда**.
- Скрипт `prepare-final-media.mjs` сжимает фото и раскладывает их в
  `prototype/public/photos/<slug>/01.jpg, 02.jpg, …` — до 1600 px по
  длинной стороне, JPEG 80, без EXIF. Это и есть то, что уходит на сайт.
- **Скрипт пересобирает все фото объекта из папки альбома**, а не
  добавляет к старым. Поэтому альбом всегда качается целиком.
- **Порядок** — по имени файла. Единственный способ поменять его —
  поле `"cover"` у объекта: указанный файл становится первым (`01.jpg`).
- **Убрать фото с сайта** — лучше всего попросить заказчика перенести
  файл в подпапку `_не для сайта` внутри альбома: подпапки скрипт не
  открывает. Если это не вариант — поле `"exclude": ["имя.jpg"]` у объекта.
- Видео объектов этой инструкцией не обновляются. Если в альбоме есть
  ролики, скрипт их пропустит и напишет об этом, это нормально.

## Шаги

Все команды — из каталога `prototype/`.

**1. Инструмент для сжатия.** Полный `npm install` здесь не пройдёт
(внутренний реестр СИБУРа недоступен снаружи), и он не нужен — нужен один
пакет `sharp` из публичного npm, отдельно от проекта:

```bash
npm install --prefix /tmp/photo-tools --no-audit --no-fund \
  --registry=https://registry.npmjs.org/ sharp@^0.35.3
ln -sfn /tmp/photo-tools/node_modules node_modules
```

Нужен Node 20 или новее (`node -v`). `node_modules` в `.gitignore`.

**2. Найти объект.** Открой манифест, найди объект по названию, запиши
его `slug` и `sourceFolders[0]`. Нового объекта в манифесте не заводи —
у объекта есть ещё координаты на карте, тексты и площадь, это делает
владелец репозитория. Если объекта нет — остановись и скажи об этом.

**3. Скачать альбом:**

```bash
node scripts/fetch-yadisk-album.mjs <slug> <ссылка на Я.Диск>
```

Скрипт кладёт файлы в папку альбома, предварительно её очистив, и
печатает список. Если нужна папка, которая лежит по ссылке не в корне,
третьим аргументом передай путь внутри ссылки: `/Папка/Альбом`.

Если скрипт не может достучаться до `cloud-api.yandex.net` — у среды
закрыта сеть. В Claude Code в браузере это настройка окружения
(Network access): нужен доступ к `cloud-api.yandex.net` и
`*.disk.yandex.net` или полный. Скажи человеку, что включить, сам не
обходи.

**4. Обложка.** Если человек назвал обложку — пропиши у объекта в
манифесте `"cover": "<точное имя файла>"`. Если не назвал, а у объекта
уже есть `cover` и этого файла больше нет в альбоме — скрипт упадёт с
понятной ошибкой: спроси человека, что ставить обложкой. Больше в
манифесте ничего не меняй.

**5. Сжать:**

```bash
PHOTOS_ONLY=1 node scripts/prepare-final-media.mjs <slug>
```

`PHOTOS_ONLY=1` обязателен: без него скрипт полезет кодировать видео, а
без slug — пересобирать весь сайт. Скрипт сам откажется работать без slug.

**6. Проверить** — и показать человеку результат, прежде чем делать PR:

```bash
ls -la public/photos/<slug>/
git status --short
```

- Фото пронумерованы подряд с `01.jpg`, их столько же, сколько фото в
  альбоме (минус `exclude`).
- Каждый файл от ~40 до ~500 КБ. Мегабайты — значит, сжатие не
  сработало.
- `01.jpg` — нужная обложка. Открой её и посмотри сам.
- В `git status` только `prototype/public/photos/<slug>/` и, если меняли
  обложку, `final-content-manifest.json`. Ничего больше.

**7. Pull request.** Ветка `photos/<slug>-<ГГГГ-ММ-ДД>`, один коммит:

```bash
git checkout -b photos/<slug>-<дата>
git add prototype/public/photos/<slug> prototype/scripts/final-content-manifest.json
git commit -m "Фото: <название объекта> — <что сделано>"
git push -u origin HEAD
```

В описании PR: объект и `slug`, ссылка на альбом, сколько фото было и
стало, какой файл стал обложкой. Мержить PR сам не надо.

**8. Дождаться проверки и превью.** Через минуту-две у PR появится
проверка «Фото — проверка и превью» (`gh pr checks`).

- **Красная** — открой лог шага «Проверка фото» (`gh run view --log-failed`):
  там по пунктам, что не так и как исправить. Исправь, закоммить в ту же
  ветку, запушь — проверка перезапустится сама. Не правь workflow и
  скрипт проверки, чтобы она прошла: исправлять нужно фото.
- **Зелёная** — в PR появится комментарий со ссылкой на превью. Открой
  его, найди объект, раскрой карточку: обложка та, фото все, порядок
  верный. Дай ссылку человеку — он показывает её владельцу сайта.

## Чего не делать

- Не коммитить папку `Финальная фактура …` и любые исходники — это
  внутренние материалы заказчика.
- Не трогать `prototype/src/data/objects.ts`: он генерируется из фото и
  манифеста при сборке, и здесь, без видео, сгенерировался бы неверно.
- Не запускать `prepare-final-media.mjs` без slug и без `PHOTOS_ONLY=1`.
- Не запускать `npm install`/`npm ci` в `prototype/`, `npm run build`,
  скрипты `deploy*.sh` и `build-manifest-from-catalog.mjs`.
- Не менять тексты, площади и остальные поля объектов — только `cover` и
  при необходимости `exclude`.
- Не трогать `.github/` и `prototype/scripts/check-photos-pr.mjs`.
- Не пушить в `main` напрямую — только ветка и PR: пуш в `main` сразу
  выкладывает фото на сайт.

## Что дальше (для человека)

Владелец сайта смотрит превью и мержит PR. Через пару минут после мержа
фото сами выкладываются на сайт (проверка «Фото — выкладка на сайт» во
вкладке Actions). На sibur.ru/ru/artnazavod изменение видно после
обновления страницы.
